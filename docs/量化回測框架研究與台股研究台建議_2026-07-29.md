# 量化回測框架研究與台股研究台建議

更新日期：2026-07-29  
研究範圍：VectorBT、Backtrader、Freqtrade、FinRL、QuantConnect LEAN。  
資料原則：只採用各專案的官方文件、官方 GitHub 原始碼庫與授權檔；本文件是工程研究，不是投資建議。

## 先說結論

這五個專案都**不應直接取代**目前 FastAPI + SQLite + 原生 JavaScript 的台股研究台。它們提供的是值得吸收的回測、風控與研究工作流；直接嵌入會帶來授權、資料市場不相符、部署複雜度或模型風險。

最合適的做法是：保留本專案的台股資料與 point-in-time（PIT）資料契約，逐步借鑑下列能力。

1. 優先：採用 Freqtrade 的「前視偏誤檢查」觀念，以及 LEAN 的獨立風控層概念。
2. 第二階段：建立本專案自己的事件式投資組合模擬器，吸收 Backtrader 的訂單／持倉／成交事件模型。
3. 研究工具：可在**隔離的開發研究環境**試用 VectorBT 做大量參數實驗；不作網站執行期依賴，且先完成授權審查。
4. 最後才做 AI：FinRL 僅適合作為離線研究原型；在 PIT 資料、基準比較與風險約束未完備前，不應把 RL 訊號用於正式推薦。

| [QuantConnect LEAN](https://github.com/QuantConnect/Lean) | Apache-2.0；Python/C# 演算法交易引擎 | 演算法框架、訂單現實模型、獨立風控模型、最佳化器 | 架構重、通常需 .NET/Docker；台股市場資料與交易規則需客製，和現有 FastAPI 架構重疊 | 借鑑架構與風控介面；暫不遷移到 LEAN |

## 個別研究

### 1. VectorBT：快速研究與大量參數掃描

官方把 VectorBT 定位為以 pandas、NumPy、Numba（另有可選 Rust engine）為核心的向量化回測；它可把多組參數與多資產放入矩陣同時運算，並提供交易、回撤與績效分析、技術指標整合、walk-forward robustness 與 Plotly 視覺化。[官方 README](https://github.com/polakowo/vectorbt#features) 也示範以費用、頻率、投資組合淨值、最大回撤、Sharpe、Sortino 等指標檢視結果。

**成熟度訊號**：官方庫有完整測試與範例目錄，README 顯示 1,000+ commits，並定位為社群版；但這些是社群／程式庫規模訊號，不等於任何台股策略有效。[官方庫](https://github.com/polakowo/vectorbt)

**授權是第一個限制**：官方明載為「Apache 2.0 with Commons Clause」，且禁止銷售主要是該軟體本身的產品或服務；外加選用依賴可能有更嚴格授權。[官方授權說明](https://github.com/polakowo/vectorbt#license) 因此不應未審查就把它打包成台股研究台的核心服務。

**可採用的方式**：

- 在 `scripts/` 或獨立研究 notebook 中，將本專案已驗證的 PIT 快照輸出成不可變資料集，再以 VectorBT 跑參數敏感度、滾動訓練／驗證、交易成本情境與績效分布。
- 將「參數格點熱圖、樣本內／樣本外分離、同時呈現最大回撤與報酬」帶回本網站；不要只挑最高平均報酬參數。
- 研究結果要存策略版本、資料截點、參數空間和所有候選結果，避免事後挑選偏誤。

**不可忽略的風險**：向量化訊號本身不會替台股處理隔日可得性、漲跌停無法成交、停牌、除權息、下市與真實委託排序；這些仍須由本專案的 PIT 與事件模擬層明確實作。

### 2. Backtrader：事件式回測的教材，不是直接依賴

Backtrader 官方描述為 Python 的回測與實盤交易平台；功能頁明列事件式交易／broker 邏輯、可向量化的指標計算、資料源、策略、指標、分析器與 sizer，並特別說明以索引 `0` 代表現在、正索引為未來，事件模式會協助抓到不當使用未來資料。[官方功能頁](https://www.backtrader.com/home/features/) [官方策略文件](https://www.backtrader.com/docu/strategy/)。

**成熟度訊號與維護提醒**：官方原始庫累積 2,400+ commits、仍有 tests 與 samples，並自稱為回測／實盤平台；但 README 中可見相當早期的資料供應註記，不能僅因歷史知名度就假設它持續追上目前 Python 與市場環境。[官方庫](https://github.com/mementum/backtrader) 這是採用風險，而非功能否定。

**授權**：官方庫明列 [GPL-3.0](https://github.com/mementum/backtrader/blob/master/LICENSE)。若把其程式直接併入或建立衍生整合，必須先確認整體散布義務；本專案不應在未確認前安裝並嵌入服務端。

**可採用的設計**：

- 建立明確的 `Signal → Order → Fill → Position → Portfolio → Risk event` 資料模型；策略只產生意圖，成交與成本交給模擬 broker。
- 每個交易日依序處理：前一日已知訊號、次日可成交價格、漲跌停／停牌、部分成交、手續費與交易稅，最後再更新淨值與風控。
- 將 analyzer 概念轉成網站統一輸出：年化報酬、最大回撤、曝險、換手率、獲利因子、交易分布及基準比較。

### 3. Freqtrade：最值得立即借鑑的「防作弊」工作流

Freqtrade 是專為加密貨幣交易所的 Python 開源交易機器人，官方 README 明載它包含回測、繪圖、資金管理與機器學習策略最佳化，並提醒先以 dry-run 驗證、不對交易結果負責。[官方 README](https://github.com/freqtrade/freqtrade#freqtrade)；它的程式庫規模（32,000+ commits、獨立 tests 與 docs）是活躍專案的訊號，但不代表可套用台股。[官方庫](https://github.com/freqtrade/freqtrade)

官方的 [lookahead analysis](https://www.freqtrade.io/en/stable/lookahead-analysis/) 會基準跑一次回測，再針對進場、出場與指標條件做切片分析，輸出疑似前視偏誤欄位；其說明也指出限價單可能造成假陽性，顯示它把回測偏誤視為需要專門測試的問題。

官方的 [Hyperopt 文件](https://www.freqtrade.io/en/stable/hyperopt/) 支援針對進出場、ROI、停損、移動停損、最大同時交易數與保護規則等空間做 Bayesian optimization，也明確提醒過度最佳化與回測／最佳化設定不一致的問題。

**授權與市場不相符**：原始庫是 [GPL-3.0](https://github.com/freqtrade/freqtrade/blob/develop/LICENSE)，而且設計目標是 crypto exchanges；不能直接套用台股盤中撮合、10% 漲跌幅、整股／零股、股利與除權息。

**本專案立即可做**：

- 新增 `lookahead_audit` 測試：對每個策略計算欄位，將日期 `t` 後的資料遮蔽或截斷，檢查日期 `t` 的訊號是否改變；改變即阻擋回測結果標示為可稽核。
- 將技術策略設為宣告式設定：`signal`, `entry`, `exit`, `risk`, `execution`, `data_requirements`；每個版本帶唯一 ID 與參數快照。
- 把最佳化限定於訓練期，驗證期凍結參數；報告同時列出所有試驗數、最佳化目標、樣本外結果和失敗結果。

### 4. FinRL：AI 研究平台，不是目前的模型解答

FinRL 官方文件說明它以 RL／DRL 訓練代理人，提供資料層、環境層與 benchmark，並把它定位為示範與教育資源，且明確非投資建議。[官方文件](https://finrl.readthedocs.io/en/latest/) 原始庫採 [MIT license](https://github.com/AI4Finance-Foundation/FinRL/blob/master/LICENSE)。

但官方 README 已清楚界定：目前 `FinRL` 保存的是原始教育、benchmark 與研究原型；要做較新的 production-oriented 架構，官方指向 FinRL-X／FinRL-Trading。它也列出原版是耦合式三層架構、使用手寫評估迴圈；這是選擇原版作學習用途而非上線交易核心的重要依據。[官方架構說明](https://github.com/AI4Finance-Foundation/FinRL#finrl-financial-reinforcement-learning--finrl-x)

**可採用的方式**：

- 只在離線實驗中，以本專案 PIT 資料建一個台股日頻環境；觀測值限於當時可得的價格、財報發布日、籌碼與市場狀態。
- 動作應受本專案既定硬限制約束：單檔上限、產業集中度、總曝險、現金下限、流動性與停損；不能讓 agent 直接決定是否繞過它們。
- 以「與 0050／加權指數、現有 vNext、等權組合」的相同成本／同曝險基準比較；必須有純樣本外期間和多個市場狀態。

**不可採用的捷徑**：不以回測 reward 最高的 agent 取代 vNext 正式資格；不把日後修訂財報或存活者宇宙餵給歷史訓練；不把 RL 產出寫成保證獲利或自動下單。

### 5. QuantConnect LEAN：最成熟的架構參考

LEAN 是 QuantConnect 的開源演算法交易引擎，原始碼庫同時含 Python 與 C# 演算法、資料處理、brokerages、orders、indicators、optimizer、research、reports 與 tests；官方庫明列 [Apache-2.0](https://github.com/QuantConnect/Lean/blob/master/LICENSE)，並顯示 13,000+ commits，是五者中最完整的交易引擎參考之一。[官方庫](https://github.com/QuantConnect/Lean)

官方演算法框架將流程拆為 Universe Selection、Alpha、Portfolio Construction、Risk Management、Execution；其中風控模組是在投資組合建構後、執行前調整或撤銷 targets，而非散落在各策略內。[官方風控概念](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/risk-management/key-concepts) 官方也提供 stop market、stop limit、trailing stop、market-on-open 等訂單類型，以及歷史資料、warm-up、rolling window 與自訂資料入口。[官方交易／資料文件](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/overview)

**適合借鑑的落地切面**：

| LEAN 概念 | 台股研究台對應設計 |
|---|---|
| Universe Selection | 資料品質 gate + 上市櫃可交易宇宙 + 排除資料過期／流動性不足股票 |
| Alpha | 綜合多因子、vNext、技術進場各自產生可追溯的 signal，不直接下結論 |
| Portfolio Construction | 依信心、波動度、產業與持倉限額形成目標權重；保留現金 |
| Risk Management | 總曝險、單檔／產業上限、停損、資料失效熔斷、過熱市場降槓桿；獨立於選股模型 |
| Execution | 台股次日可得性、成交額、滑價、漲跌停、交易成本、除權息與部分成交規則 |

**不建議現在直接遷移**：本專案是 FastAPI／Python／原生前端，LEAN 是完整多語言引擎，部署、資料格式和台股資料／券商接頭都需重新建置。即使使用它的 custom data 機制，也不能自動取得正確的台股 PIT 財報、交易制度或券商成交模型。因此先採其模組邊界和測試方法，效益遠大於直接替換。

## 建議的升級路線與驗收

### P0：讓既有回測「可信」

1. 建立所有策略共用的 `StrategyRun` metadata：策略版本、程式版本、資料截點、PIT 可得性規則、股票宇宙、成本、滑價、參數與基準。
2. 實作 Freqtrade 式前視偏誤稽核：截斷未來資料後，歷史時點的指標／訊號必須一致；失敗時頁面顯示「不可稽核」，不得列入策略成績。
3. 對台股新增成交現實性：次日可成交判斷、漲跌停／停牌、成交額上限、手續費、賣出證交稅、現金股利；股票股利、下市與存活者偏誤須先明確揭露並列為缺口。

**驗收**：每一次回測可重現；同一資料截點與設定重跑結果相同；故意在指標中加入 `t+1` 資料的測試會被稽核擋下。

### P1：從逐筆交易升級為投資組合回測

1. 以 Backtrader／LEAN 的分層概念實作本專案原生事件模擬器，先只支援台股日頻。
2. 先做 long-only、現金帳、整股與明確的成交價格假設；支援同時持股上限、單檔上限、產業上限、總曝險和風險預算。
3. 以同現金比例的加權指數／0050（資料可用時）作基準，固定期間同時輸出年化報酬、最大回撤、波動、Sharpe、換手、交易數、曝險與落後月份。

**驗收**：技術進場研究不再只給「每筆平均淨報酬」，而能給固定初始資金的淨值曲線與回撤；vNext、綜合模型和基準使用完全一致的執行假設。

### P2：研究加速與 AI，保持隔離

1. 以 VectorBT 做離線敏感度實驗，輸出完整候選參數表；只有通過未來資料稽核與樣本外驗證的固定設定，才可手動登錄至網站策略設定。
2. 以 FinRL 建立純研究台股環境，先使用月／季再平衡，加入交易成本與硬風控；不接正式推薦。
3. 對每個 AI／最佳化實驗保存隨機種子、訓練／驗證／測試切分、特徵發布時間、超參數與失敗 runs。

**驗收**：任何「較佳」結果都能顯示相同期間基準、樣本外與不同市場狀態的表現；無法通過者只能標示研究結果，不能升格為推薦規則。

## 最終採用決策

- **直接安裝為網站依賴：目前全部否。**
- **立即採用：Freqtrade 的 lookahead-audit 方法、LEAN 的獨立風控邊界。**
- **離線研究候選：VectorBT（先確認 Commons Clause）、FinRL（研究沙盒）。**
- **架構教材：Backtrader、LEAN。**

這個順序能先解決目前回測最關鍵的問題──資料可得性、前視偏誤、成本、同曝險基準與資金限制──再談加速搜尋或 AI；不會把外部框架名稱誤當成模型有效性的證據。
