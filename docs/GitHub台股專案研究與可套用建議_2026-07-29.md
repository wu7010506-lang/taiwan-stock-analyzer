## 可直接套用：資料品質與同步可靠度

`qlib-tw-trader` 的 README 將 TWSE、FinMind、Yahoo 的來源優先順序、fallback 與 coverage tracking 放在資料同步工作流中，並設有資料品質儀表板；其目錄也將 adapters、services、tests 分層。[來源：README 的資料與架構說明](https://github.com/Docat0209/qlib-tw-trader#data-pipeline)。

建議本專案在既有 `data_quality_snapshots` 外，新增或補齊下列可稽核欄位（不以「最後一次成功」掩蓋缺口）：

| 項目 | 建議欄位／規則 |
| --- | --- |
| 每一資料集 × 股票 | `source_used`、`source_priority`、`coverage_start/end`、`expected_rows`、`actual_rows`、`fresh_until`、`schema_version`、`content_hash`。 |
| 每一次抓取 | `run_id`、`attempt`、`started_at`、`finished_at`、HTTP／解析錯誤分類、`next_retry_at`、`terminal_failure`。 |
| 正式推薦閘門 | 對每個資格資料集保存 `eligible` 與 machine-readable `ineligible_reasons`；只要財報、現金流、價格或新鮮度未達門檻，即不可進 vNext 正式名單。 |
| 來源替代 | 每個 adapter 回傳同一標準結果：資料列、涵蓋範圍、來源、警告及可重試錯誤；只有通過 schema、日期連續性與合理值檢查才可切換為成功。 |
| 批次完成定義 | 將「全市場同步完成」分為 succeeded、partial、failed；partial 必須列出遺漏股票與資料集，不得把快照標成完整。 |

FinMind README 列出本專案所需的台股日價、財報、資產負債、現金流、月營收與法人買賣資料，並說明資料每日更新。[來源：FinMind README](https://github.com/FinMind/FinMind#what-is-this)。其[官方使用條款](https://finmind.github.io/PrivacyPolicy/)說明每週日 00:00–03:00 的維護窗，且 API 有方案相關限額。因此排程應：

1. 以每個來源的限流器與指數退避（含 jitter）處理暫時性錯誤；不要以整批重新下載取代缺口補抓。
2. 維護窗及連續失敗時標示「延遲／來源失敗」，保留上次成功資料日期與下一次重試時間。
3. 對每日收盤任務建立獨立全市場工作佇列，先同步股票主檔與交易日，再分資料集分片；個股頁搜尋只能補救，不得成為正式資料的新鮮度來源。
4. 在 `/data-quality/` 顯示整體與「可正式推薦母體」兩個 coverage，並可下載／查看任一快照的失敗清單。

`twstock` README 提供證券清單更新、TWSE／TPEx 資料抓取與對 TWSE 的三次請求／五秒節流提醒。[來源：README](https://github.com/mlouielu/twstock#readme)。可把它的官方端點與節流策略當成第二來源 adapter 的測試依據；它不是 PIT 財報或全市場正式推薦資料的完整替代品。

`tw_stocker` 將每檔 CSV 的欄位、起訖日、筆數、檔案大小與 SHA-256 納入 `data/manifest.json`，並以 `build_catalog.py --check` 驗證。[來源：README](https://github.com/voidful/tw_stocker#tw-stock-data)。可在 SQLite 實作等價的 `dataset_manifest`：同步後產生 coverage／row count／hash，資料品質快照只引用 immutable manifest id，讓後續決策履歷能重建所見資料版本。

## 可直接套用：vNext 的 PIT／walk-forward 回測

`qlib-tw-trader` README 描述 156 週 walk-forward：每週模型僅使用過去資料；交易日 T 的特徵只取到 T-1 收盤，train／validation 間保留七日 embargo。[來源：README 的回測方法](https://github.com/Docat0209/qlib-tw-trader#walk-forward-backtest)。可直接轉換為 vNext 的最小規格：

1. 建立 `as_of_date` 與 `published_at`：財報、月營收、股利與估值只能在公告／取得時間已不晚於決策日的版本出現；價格特徵最晚至 T-1，訊號在 T 收盤後產生則最早 T+1 成交。
2. 每個 rebalance date 都依當日 eligibility 重建股票池，包括當時已下市／停止交易或資料不足的股票；不可用今日上市清單回填歷史母體。
3. 固定 train、validation、test 的時間窗，加入至少七個交易日 embargo（實際天數應依持有期與標籤重疊評估），並輸出 fold 的 universe、資料版本、參數、訊號、訂單、成本與績效 artifact。
4. 成交使用下一交易日的可取得價格，套用手續費、證交稅、滑價、最低流動性與不可成交處理；現金股利以除息與入帳規則納入。另列出尚未處理的股票股利、下市、存活者偏誤等限制。

`purged-cross-validation` 提供 `WalkForwardSplit`、`PurgedKFold`、purge／embargo、CPCV 路徑重建，以及 leakage／embargo diagnostics 與 PSR、DSR、PBO 等回測過度選擇檢查。[來源：README](https://github.com/eslazarev/purged-cross-validation#purged-cross-validation)。在 vNext 實作時，先不必引入該套件；應先將下列驗收測試寫入目前測試組：

- 任一 fold 的訓練資料 `published_at` 不得晚於該 fold 決策日。
- 所有帶持有期間標籤的 train／test 樣本區間不得重疊；embargo 後才允許下一段資料進訓練。
- 相同歷史資料庫快照、相同設定與隨機種子重跑，輸出應相同（包含 universe 與排序 tie-break）。
- 回測報表顯示每 fold 的 coverage、被排除股票數與原因、交易筆數、成本、股利、現金比例、最大回撤；資料缺口不得靜默補值。

## P1 投資組合風控的後續借鏡

`cvxportfolio` 有 market-data abstraction、交易／持有成本與限制式投資組合政策等結構，適合用來設計「策略產生候選」與「風控決定可下單權重」兩層責任。[來源：專案 README](https://github.com/cvxgrp/cvxportfolio#cvxportfolio)。由於 GPL-3.0，僅以觀念重寫：

- `portfolio_constraints`：單檔上限、產業上限、總股票曝險、最低現金、流動性上限。
- `risk_budget`：依市場狀態、波動與回撤下調總曝險；將未用風險預算顯示為現金，而非強制買滿。
- `order_constraints`：依當日量能限制成交金額與滑價，並完整記錄被拒絕或被縮減的訂單理由。

## 建議實作順序

1. 將同步 run／資料集 manifest／來源結果持久化，並先讓 `/data-quality/` 顯示「正式推薦可用母體」與終止失敗清單。
2. 為每個基本面資料加入 `published_at`／`as_of_date`；先寫 PIT guard tests，再做 vNext 小樣本 walk-forward。
3. 對完整股票池跑可重現的 weekly walk-forward，輸出 artifact 與全部限制揭露；確認後才向 UI 呈現任何年化／勝率指標。
4. 將推薦輸出交給獨立 portfolio constraint 層；先提供建議權重和拒絕理由，不自動交易。

## 採用時的限制

- GitHub 專案的公開 README、星數或近期更新，只能作為維護線索，不能取代資料正確性、授權、PIT 完整性或策略有效性的驗證。
- FinMind 軟體授權與資料授權不同；即使程式碼可使用，也必須持續遵守資料服務的用途、展示、再散布與速率條件。
- 以上回測設計可降低前視偏誤，但仍需公開揭露未涵蓋的公司行為、下市與歷史成分股資料限制，且不代表實盤報酬或保證獲利。
