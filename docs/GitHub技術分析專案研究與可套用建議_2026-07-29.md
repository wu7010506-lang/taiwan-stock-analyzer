# GitHub 技術分析專案研究與可套用建議

更新：2026-07-29。範圍限於可與本專案（FastAPI、原生 JavaScript、TWSE／TPEx、SQLite）搭配的技術指標、K 線型態、回測與台股資料來源。以下以各專案的 README、LICENSE 與原始碼樹為準；「維護狀態」只是本次查核時的訊號，並不保證未來支援。

## 結論

最合適的路線不是把一個交易框架整包併入產品，而是：**資料仍由目前同步器與官方備援掌控；在後端建立可測試的指標計算層；回測引擎保留本專案的 point-in-time 資料與台股交易規則。**

建議優先採用的外部元件只有兩類：

1. **TA-Lib Python** 作為可選的指標／K 線型態計算器（BSD-2-Clause）；本機安裝與版本鎖定成功後才啟用，並保留純 pandas 的核心指標備援。
2. **FinMind、twstock** 僅作為資料格式、資料來源與限流策略的參考／備援候選；兩者都不應取代本專案的資料新鮮度、覆蓋率與 PIT 追蹤。

回測不可直接以通用框架的預設績效當作 vNext 成績。台股漲跌幅限制、整股／零股、成交量容量、手續費／交易稅、除權息、股票股利及 PIT 可得日都必須由專案明確實作與揭露。

## 1. 技術指標與 K 線型態

### TA-Lib Python：推薦作為「可替換計算器」

[README](https://github.com/TA-Lib/ta-lib-python) 明列 ADX、MACD、RSI、Stochastic、Bollinger Bands 等 150+ 指標與 K 線型態辨識，且 Function／Abstract API 可直接接受 OHLCV 的 Pandas DataFrame。其 LICENSE 為 [BSD-2-Clause](https://github.com/TA-Lib/ta-lib-python/blob/master/LICENSE)，適合商用產品整合。

可採用功能：

- `SMA/EMA/RSI/MACD/ADX/ATR/BBANDS/OBV` 作為技術面特徵的一致實作；輸入統一為依交易日排序、無重複日期的 `open/high/low/close/volume`。
- K 線型態函式（如吞沒、十字、錘頭）只產生「觀察訊號」，不直接形成買賣指令；回傳型態名稱、方向、lookback、最後一根日期與價格資料品質。
- 指標輸出的 warm-up NaN 必須保留並顯示「資料不足」，不可填 0。README 特別說明不同指標所需的 lookback 不一定等於參數期數，且 NaN 傳遞行為與 pandas rolling 不同，應用 golden tests 固定期望值。

整合警告：雖然新 wheel 已包含底層 C library，仍要在 Windows 的 `.local-packages/` 實際安裝驗證；README 也明說舊環境可能須安裝底層庫。把其放在 `app/technical_indicators.py` 的 adapter 後，提供 `engine="talib" | "pandas"`，不要讓 API route 或前端直接 import TA-Lib。

### 純 pandas／NumPy：核心指標的必要備援

SMA、EMA、報酬率、成交量均線、歷史高點距離及簡單 ATR 可以維持專案自算，優點是部署穩定與公式完全可稽核。這不是要重造 150 個指標，而是讓正式推薦依賴的少數指標有無 C 擴充的確定行為。新增測試應比對固定 OHLCV fixture 的輸出，以及空值、停牌／缺日期、未滿 lookback 的處理。

### pandas-ta-classic：適合廣泛研究，不作正式真相來源

[pandas-ta-classic](https://github.com/xgboosted/pandas-ta-classic) 是原 pandas-ta 的社群維護分支；README 說明有 192 個指標／工具、62 個原生 candle patterns，並可選擇以 TA-Lib 加速；[MIT LICENSE](https://github.com/xgboosted/pandas-ta-classic/blob/main/LICENSE) 可相容於本機產品。它適合研究頁快速增加不影響正式模型的指標（例如 VWAP、Choppiness、支撐壓力輔助欄）。

但指標名稱、預設參數與公式演進仍需 lockfile／精確版本固定，並用專案的 canonical fixture 驗證。原 `twopirllc/pandas-ta` 的公開連續性在本次查核不可靠，故不應直接鎖為長期依賴。

### 台股 K 線要額外處理的語意

任何函式庫都只看到 OHLCV，並不知道台股的漲跌停、除權息、交易單位或異常／停牌。因此資料層需保留：`price_date`、是否調整價、來源、是否完整交易日、企業行動標記。K 線型態不得跨越缺失交易日悄悄補值；型態訊號也須在 UI 顯示「技術型態為歷史價格描述，非獲利保證」。

## 2. 台股資料與資料品質

### FinMind

[FinMind README](https://github.com/FinMind/FinMind) 為 Apache-2.0，提供 `TaiwanStockPrice`，其測試原始碼亦可核對日價量欄位（`open/max/min/close/Trading_Volume`）與台股資料載入方式：[test_data_loader.py](https://github.com/FinMind/FinMind/blob/master/tests/data/test_data_loader.py)。README 明示未驗證 token 的 300 requests/hour、token 600 requests/hour 及每週維護時段；這些應餵進同步器的速率限制與來源狀態，而非在失敗時重試到無限。

可採用：作為日 OHLCV 候選來源、欄位正規化 fixture、來源健康度量測。不可採用：把今日 API 修正過的歷史資料回填成當年已知資料；vNext PIT 必須保存抓取／公告可得時間與當時資料版本。

### twstock

[twstock README](https://github.com/mlouielu/twstock) 與 [MIT LICENSE](https://github.com/mlouielu/twstock/blob/dev/LICENSE) 指明資料來源含 TWSE 與 TPEx，並警告 TWSE 限制為每五秒三個請求。可將它的市場代號處理與「來源失敗可退回官方」做為備援設計參考，或在隔離 adapter 中驗證；不得在全市場同步直接高併發呼叫。

README 的 `BestFourPoint` 只是示範型規則，不能列為正式推薦模型。若展示它，需標為教育型技術訊號、提供計算日期及無資料原因。

### Twse-stock-crawler：只借鏡模組切分

[README](https://github.com/s311354/Twse-stock-crawler) 的策略外掛抽象、純服務的指標／收益計算、以及 CSV/SQLite/DuckDB repository 分層值得借鏡；它的 Low Entry v3 使用 EMA20/50/200、RSI14、MACD、布林、ATR、OBV、支撐與 higher-low，適合轉成「可解釋的技術觀察面板」。但它的提交量少且未看到可替代目前資料品質契約的 PIT／除權息治理，故不直接導入程式或規則分數。

## 3. 回測、成本與可稽核性

### 不要把通用回測引擎當成 vNext 正式成績

[VectorBT README](https://github.com/polakowo/vectorbt) 主打 NumPy、Numba、Rust 的大規模參數矩陣回測及交易層級組合分析，適合離線探索「參數是否太多、是否過度擬合」。但其 [LICENSE.md](https://github.com/polakowo/vectorbt/blob/master/LICENSE.md) 是 Apache-2.0 with Commons Clause，對銷售以該軟體為實質基礎的產品／服務有限制，不能把它當一般 Apache 依賴。正式 vNext 仍應逐日依當時資料快照選股、重建可投資股票池、處理台股成本及容量；因此僅在核可後的隔離內部研究環境交叉驗證小型策略，或只閱讀其設計。

[backtesting.py README](https://github.com/kernc/backtesting.py) 的 `Strategy.init/next`／crossover API 易讀，卻採 AGPL-3.0（[LICENSE](https://github.com/kernc/backtesting.py/blob/master/LICENSE.md)）。除非專案接受其散布條件並經法務確認，不能在本機網站服務端直接安裝成產品依賴；可以閱讀其成本、訂單與 trade 統計設計。

[Zipline Reloaded](https://github.com/stefan-jansen/zipline-reloaded) 為 Apache-2.0 的 event-driven 歷史模擬器，值得參考 calendar、asset、訂單生命周期與交易成本的模型化；但它預設的 bundle／資產／市場日曆周邊偏美股，將台股公司行動、上市櫃標的與交易日整合進去的成本很高。因此不作目前 FastAPI 應用的直接依賴。

### 應在本專案新增的回測契約

1. 每個 rebalancing date 讀取 `as_of` 快照：價格只能到前一已收盤日；財報／營收／股利以公告或實際入庫可得時間為準。
2. 先檢查正式推薦資格、資料新鮮度、流動性與停牌；不合格者記錄排除原因，絕不以零分混入排名。
3. 交易以次一可交易日的保守價格規則成交，並把手續費、交易稅、滑價、最小交易單位、成交量上限寫成版本化參數；每筆交易保存成本拆解。
4. 現金股利以權息日／實際支付規則一致地入帳；股票股利、下市、合併及存活者偏誤若尚未處理，要在 API、頁面與報告明確列出。
5. 輸出每期 universe、訊號、訂單、成交、現金、淨值及未成交原因。這比只輸出 CAGR／勝率更能重跑與稽核。

## 4. 建議實作順序（不在本次直接修改）

1. 建立 `TechnicalIndicatorService`：輸入資料品質 metadata 與 OHLCV、輸出指標值／warm-up／計算引擎／資料截止日；先完成 pandas baseline 和 fixture tests。
2. 將 TA-Lib 設為 optional extra，安裝成功才開啟；對 SMA、EMA、RSI、MACD、ATR、BBANDS、OBV 建立與 baseline 的容差測試。K 線型態另設為非正式訊號。
3. 個股頁與推薦頁展示相同的「計算截至日、有效樣本數、資料來源、缺口、風險」；技術訊號不覆蓋既有基本面／市場狀態的獨立約束。
4. 在現有 vNext walk-forward 工作上加入上述逐期 ledger 與成本模型，再用 vectorbt／手算小 fixture 作離線交叉驗證，而不是改用它作正式引擎。

## 驗收清單

- 同一 OHLCV fixture 在 pandas 與 TA-Lib adapter（若已安裝）對核心指標結果一致，warm-up 與 NaN 行為有明確測試。
- 任一股票不足指標 lookback、OHLCV 有缺日或來源過舊時，API 回傳資料不足原因，不產生偽訊號。
- 台股來源退避、限流與失敗批次會反映在 `data_quality_snapshots`，且不會因重試壓垮來源。
- 回測重跑可列出某日所有候選、排除原因、所用 as-of 資料版本及每筆成本；不使用未來公告資料。
- 任何 K 線／技術指標／回測頁都包含非保證獲利、資料與企業行動限制的揭露。
